# SplotLabs organization repository

This repository owns the organization profile and shared contribution policies.
Use [README.md](README.md) to find the policy that applies.
Get the owner's explicit decision before changing contribution, licensing, or privacy terms.
Check profile claims against the Splot README.

Commit, push, open a pull request, or merge only when the task authorizes that action.
If the owner requests autonomous work or assigns a GitHub issue, continue through review, checks, and merge.
The approval requirements for policy terms still apply.

## Defects found during work

Use this procedure here and in projects that refer to it.
Report security-sensitive findings privately as directed in [CONTRIBUTING.md](CONTRIBUTING.md).
Keep private project information, personal data, and proprietary samples out of public reports.

1. Identify the repository that owns the failing behavior.
2. If the task permits the fix, fix the defect there during the session.
   Verify the fix. Keep unrelated fixes in separate changes.
3. If the fix must wait, use the owning repository's issue tracker for findings that you can disclose there.
   Search for an existing issue first.
   Add any new evidence there. If no issue covers the defect, open one before handover.
4. Describe the expected and observed behavior. Include the affected revision and the smallest available reproduction or evidence.
   State what prevents the fix. Link the issue at handover.
5. If you cannot file the issue, give the owner the repository, issue text, and reason at handover.

Filing an issue does not authorize a change to another repository or waive a required check.
